Overview

Video generation models are increasingly viewed as world simulators, which requires not only plausible motion but dynamics that respond correctly to specified physical parameters. Existing benchmarks largely target perceptual plausibility, leaving this physical parameter responsiveness insufficiently explored. A model that renders a beautiful tabletop and then ignores gravity can still score well.

PhysResponse measures the gap at two levels. Scene-conditioned simulator inversion recovers the effective gravity, friction and initial speed of a generated video: every clip starts from a known simulated scene, so we replay that exact scene at many parameter values and keep the values whose rendered boxes match the tracked boxes. Event evaluation then tests the outcomes, near and across the critical transitions where a small change of a parameter flips what happens.

  • The two levels fail independently. A video can be visually stable and physically wrong, or follow the parameter while breaking the event chain. A still frame scores 37.8 dB PSNR, higher than all ten evaluated models (21.0–31.0 dB); a physically correct video shows 3.6 % gravity error against 73.5–140.3 % for the models.
  • Ground-truth parameters are exact. Inputs come from a simulator, so the true g, μ and v are known for every reference, and every video is scored on the same task, prompt and physical clock.
  • Inversion explains more than a curve fit. On reference videos with known parameters, inversion reaches 3.0 %, 7.0 % and 1.4 % error on g, μ and v; image-plane fitting and monocular depth lifting explain free flight only, with coverage below 8 %.

Benchmark

Physical responsiveness is measured at two levels, because a model can be visually stable and physically wrong, or follow a parameter while breaking the event chain.

Level 1

Parameter level

Tracking → conditional simulator inversion → effective parameters. Given the tracked boxes and the task's own scene, we replay that scene at many parameter values and keep the ones whose rendered boxes match the video.

The result is the effective gravity g, friction μ and initial speed v of the generated motion, with the other conditions held at their prompted values — a conditional estimate, not an identification of every parameter from one trajectory.

Level 2

Event level

Reference events → generated events → outcome scoring. A per-event reading of the video: did the cascade arrive, did the second contact happen, in what order. Each registered pair has unit weight, shared equally among its targets. A target is correct when both endpoints match their own reference outcomes.

Critical transitions are the stress test of this level: samples placed at known distances on both sides of a verified boundary, where one outcome flips into another.

Qualitative examples

Book dominoes (T06) at three gravity levels. One row per condition, one column per time step measured from the conditioning frame; every row advances on the same clock, so only the conditions differ between rows.

Across a critical boundary

Task T09, a stack of books under two gravity levels. The upper target book stays on the stack at 3.71 m/s² and lands on the table at 9.81 m/s². The transition is the measurement: a model that produces the same outcome at both ends has not responded to gravity, whatever the video looks like.

Getting started

The package builds the generation manifest, tracks every moving object, compensates the camera, inverts the simulator and writes the model's row of the main table. A step whose output already exists is skipped, so an interrupted run resumes where it stopped.

Code, benchmark downloads, and installation instructions will be linked here when released.
